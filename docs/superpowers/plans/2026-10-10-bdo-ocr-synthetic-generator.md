# BDO OCR Synthetic Dataset Generator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate deterministic warehouse and inventory screenshots with exact per-slot labels and no new runtime dependencies.

**Architecture:** A Node ESM CLI reads published item icons from a caller-provided catalog directory, composes BDO-inspired panels as SVG, and renders JPEGs with the Sharp already installed by `apps/api`. One local JSON manifest carries all sample and slot ground truth.

**Tech Stack:** Node.js 24, ESM, Sharp from `apps/api`, `node:test`.

**Spec:** [2026-10-10-bdo-ocr-dataset-pipeline.md](../specs/2026-10-10-bdo-ocr-dataset-pipeline.md)

## Global Constraints

- Use the existing `sharp` dependency resolved from `apps/api/package.json`; add no package dependencies.
- Keep all generated images and manifests under `tmp/ocr-dataset/synthetic/`; ignore `tmp/ocr-dataset/` in Git.
- Use only IDs and WebP icons from the supplied published catalog’s `asset_redirects.json`.
- Record exact pixel bounds in final-image coordinates and preserve the displayed text separately from normalized values.
- All CLI logs and errors contain no emoji; never delete or overwrite an unmarked caller directory.

## Review Focus

- Missing, invalid, or empty catalog: reject with actionable error; test corrupt/missing manifest and missing icon.
- Unsafe icon path: reject traversal and unsupported extensions before reading; test `../` and non-WebP paths.
- Seed stability: same seed and configuration produce identical manifest labels and bytes; test same-seed and changed-seed cases.
- 8/9 column boundaries at all output sizes: no slot box may clip or escape the image, and slot pitch stays inside the reader's supported 14–160 px range; test every column count/resolution and 100/110/120% scale.
- Occupied versus empty slots: occupied slots get exactly one label and empty slots none; test quantities, suffixes and I–X labels.

### Task 1: Implement the generator, manifest, and local safeguards

**Files:**

- Create: `scripts/generate-synthetic-ocr-dataset.mjs`
- Create: `scripts/generate-synthetic-ocr-dataset.test.mjs`
- Modify: `.gitignore`

**Interfaces:**

- `parseGeneratorArgs(argv)` returns validated `{ count, seed, split, outputDir, catalogDir, overwrite }` or help text.
- `readPublishedIconCatalog(catalogDir)` returns `{ itemId, absolutePath }[]` for valid `urn::item:<id>` WebP aliases only.
- `buildSyntheticSample({ sampleId, seed, width, height, uiScale, columns, panelType, noiseLevel, jpegQuality, catalog })` returns `{ image: Buffer, sample: GroundTruthSample }`.
- `generateSyntheticDataset({ count, seed, split, outputDir, catalogDir, overwrite = false })` writes JPEGs and version-1 `ground-truth.json`, then returns `{ sampleCount, manifestPath }`.
- `GroundTruthSample` records `id`, relative `path`, SHA-256, `width`, `height`, `seed`, `split`, `uiScale`, `noiseLevel`, `jpegQuality`, `panelType`, `grid: { left, top, columns, rows, slotWidth, slotHeight }`, and every occupied/empty slot’s row, column, exact slot bounds, optional `labelBounds`, item ID, label kind, displayed text, normalized value, and `approximate` flag. A subset of occupied equipment-item icons in inventory grids carries a Roman overlay so Roman reading remains in realistic inventory context.
