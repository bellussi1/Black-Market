# Black Market: funcionalidades e cobertura

Revisão: 7 de outubro de 2026. Referências funcionais: [pesquisa dos sites](product-research.md). Interface e implementação próprias.

O objetivo é uma plataforma pública brasileira com consultas gratuitas e planejamento personalizado, descrito em [visão do produto](product-vision.md). Esta matriz relata o estado do código; armazenamento local e ausência de login são limites atuais da implementação. ## Persistência e operação

A primeira extração SA/pt já foi importada: 74.216 itens, 212 categorias, 4.406 receitas distintas e ícones para 70.556 IDs. As receitas identificam subprodutos. Outros conjuntos extraídos ainda não foram integrados às funcionalidades.

O catálogo usa PostgreSQL. Cotações guardadas e dados pessoais usam o navegador nesta fase; limpar o armazenamento remove esses registros. O cache Arsha fica em memória da API e é perdido no restart. A consulta não realiza ingestão massiva, não roda um cron e não persiste histórico global em PostgreSQL.

As calculadoras rodam com o mesmo pacote de regras no Angular e no NestJS; o botão de verificação chama a API. A validação de backups limita versão, tipos, tamanhos e IDs duplicados. Falha de armazenamento mantém a sessão em memória e orienta exportar um backup. Dados locais corrompidos são preservados para recuperação e não são sobrescritos por edições comuns.

O repositório foi renomeado para [bellussi1/Black-Market](https://github.com/bellussi1/Black-Market), mantendo sua visibilidade privada. O Docker Compose também usa o nome black-market. O diretório local, o banco PostgreSQL e seu volume existente conservam os identificadores físicos; POSTGRES_DATA_VOLUME no .env local preserva o volume durante a mudança.
